# CC: Power

**Потребление RF-энергии компьютерами и черепахами из [CC: Tweaked](https://modrinth.com/mod/cc-tweaked).**

Minecraft 1.15.2 – 26.3 · Forge / NeoForge / Fabric · требует CC: Tweaked

[English](README.md) · [Русский](README.ru.md)

В Fabric-сборках энергоАПИ встроена в джарку (Team Reborn Energy) —
дополнительные моды не нужны. Каждая версия живёт в своей ветке
`mc/<версия>` этого репозитория. Интеграция с Jade включена в современные
NeoForge-сборки (Jade не обязателен).

Компьютеры и черепахи из CC: Tweaked становятся настоящими потребителями
энергии. Они тянут RF/FE (энергосистема Forge, которую используют Thermal,
Mekanism, Create: Power Grid и множество других технических модов) и
прекращают работу, когда энергия заканчивается.

## Как это работает

### Компьютеры

- У компьютера есть **небольшой внутренний RF-буфер** (он — часть блока)，
  который пополняется от **соседних блоков** с FE-энергией: энергоячейки,
  кабели, машины — всё, что предоставляет энергокапабилити NeoForge.
- Каждый игровой тик включённый компьютер платит:
  `постой + (программа работает ? активная : 0) + цена каждой подключённой
  периферии + надбавки за вызовы`.
- Если буфер не покрывает стоимость тика — компьютер **выключается**
  (обычный shutdown CC: идущая программа теряется). Включение ручное, и оно
  **гейтируется**: компьютер не стартует, пока в буфере не наберётся хотя бы
  `постой + активная` RF.
- Выключенный компьютер буфер пополняет, но ничего не потребляет.

### Черепахи

- Черепаха — это компьютер, который двигается, поэтому она идёт **по тому же
  коду**, что и стационарные компьютеры: тот же тиковый счёт, те же
  периферии, те же вызовы.
- У неё **небольшая внутренная RF-батарея**, и нужны **два вида топлива**:
  * ванильное топливо черепахи (без изменений) — чтобы **двигаться и
    действовать**,
  * RF-энергия — чтобы **исполнять код**.
- Кончилась RF — черепаха замирает на месте. Кончилось топливо — как в
  ванили. **Действия** черепахи (движение, копание, установка блоков...)
  также стоят немного RF за каждое.
- Заряжайте черепах на **дроностанции**.

### Дроностанция

`ccpower:dock` — блок, который тянет FE из шести соседних блоков во
внутренний буфер и заряжает стоящую на нём черепаху.
Рецепт: железо + блок редстоуна + громоотвод.

## Цены по типам периферий

`config/ccpower-peripherals.toml` **генерируется и ведётся самим модом**:

- при старте сервера все установленные моды **просканированы**, и все типы
  периферий, которые они могут предоставить, записаны в файл, сгруппированы
  по модам;
- две независимые цены на каждый тип:
  `[rf_per_tick]` — платится каждый тик, пока периферия подключена,
  `[rf_per_call]` — платится за каждый вызов;
- незнакомые типы, встреченные в мире позже, дописываются автоматически;
- файл **перечитывается на работающем сервере** — правки применяются за ~2
  секунды без перезапуска.

Дефолты учитывают тип: предметные хранилища (сундук, хоппер, печка, шалкер)
стартуют с 15 RF/вызов, монитор — 4, модем — 2 (база
`power.peripheralCallRF` = 5). У каждого типа всегда есть обе цены; чтобы
обнулить цену, поставьте `0.0`.

## Динамические конфиги

`config/ccpower-common.toml` (конфиг NeoForge, перечитывается на ходу):

| Ключ | Дефолт | Значение |
|---|---|---|
| `power.idleRFPerTick` | 2 | Постой включённого компьютера за тик |
| `power.activeRFPerTick` | 10 | Надбавка, пока работает программа |
| `power.computerBufferRF` | 2000 | Ёмкость буфера стационарного компьютера |
| `power.computerPullRFPerTick` | 1000 | Скорость подтяжки RF от соседей, RF/тик |
| `power.peripheralRFPerTick` | 1 | Дефолт тик-цены для новых типов |
| `power.peripheralCallRF` | 5 | Базовая цена вызова (по типам — множители) |
| `power.surchargeCapPerTick` | 1000 | Потолок надбавок за вызовы в один тик |
| `turtle.actionRF` | 4 | RF за действие черепахи (ход, копание...) |
| `turtle.bufferRF` | 20000 | Ёмкость батареи черепахи |
| `dock.bufferRF` | 50000 | Буфер дроностанции |
| `dock.pullRFPerTick` | 1000 | Скорость подтяжки дроностанцией, RF/тик |
| `dock.chargeRFPerTick` | 250 | Скорость зарядки черепахи, RF/тик |
| `logging.*` | — | Что мод пишет в лог |

## Jade

С установленным [Jade](https://modrinth.com/mod/jade) при наведении на
компьютер, черепаху или дроностанцию показывается уровень их буфера/батареи
в виде полоски — той же универсальной шкалы энергии, которую Jade рисует для
FE-хранилищ, включая стандартную цифровую подпись «текущее / ёмкость FE».
Jade необязателен.

Администратор может включить дополнительную строку диагностики командой
`/ccpower debug` — в ней показываются скорости зарядки и разрядки в РФ/тик
и текущий буфер компьютера. Флаг действует на игрока и не сохраняется между
сессиями.

## Lua API

Полное описание всех методов с примерами: [docs/API.md](docs/API.md).

У каждого компьютера есть API `ccpower`:

| Метод | Возвращает |
|---|---|
| `ccpower.getEnergy()` | Текущее количество РФ в буфере/батарее |
| `ccpower.getCapacity()` | Ёмкость хранилища |
| `ccpower.getChargeRate()` | РФ, полученные за последний игровой тик |
| `ccpower.getDischargeRate()` | РФ, потраченные за последний игровой тик |

Скорости измеряются за один игровой тик (РФ/тик). Выключенный компьютер
продолжает сообщать о получаемой зарядке.

Дроностанция — это ещё и периферия типа `ccpower_dock`. Соседний компьютер
(или проводной модем) может читать её внутреннее состояние:

```lua
local dock = peripheral.find("ccpower_dock")
dock.getEnergy()       -- РФ в буфере станции
dock.getCapacity()     -- ёмкость буфера
dock.getPullRate()     -- РФ/тик, подтянутые от соседей
dock.getChargeRate()   -- РФ/тик, отданные черепахе
```
